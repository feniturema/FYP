## 6. 实现契约

### 6.1 `scripts/lib/wait.sh`

```bash
# shellcheck shell=bash
# wait_http URL TIMEOUT_S [PID] [LOG]
# return 0 = ready, 1 = timeout, 2 = watched process exited. Prints last 80 log lines on failure.
wait_http() {
  local url=$1 timeout=$2 pid=${3:-} log=${4:-}
  local deadline=$(( SECONDS + timeout ))
  while (( SECONDS < deadline )); do
    if [[ -n $pid ]] && ! kill -0 "$pid" 2>/dev/null; then
      echo "wait_http: process $pid exited before $url was ready" >&2
      [[ -n $log && -f $log ]] && tail -n 80 "$log" >&2
      return 2
    fi
    if curl -fsS -o /dev/null --max-time 5 "$url"; then return 0; fi
    sleep 2
  done
  echo "wait_http: timeout after ${timeout}s waiting for $url" >&2
  [[ -n $log && -f $log ]] && tail -n 80 "$log" >&2
  return 1
}
# wait_cmd TIMEOUT_S DESCRIPTION -- CMD [ARGS...]   (retries CMD until exit 0)
wait_cmd() {
  local timeout=$1 desc=$2; shift 2
  [[ ${1:-} == -- ]] || { echo "wait_cmd: missing -- before command: $desc" >&2; return 2; }
  shift
  (( timeout > 0 )) || { echo "wait_cmd: timeout must be positive: $desc" >&2; return 2; }
  (( $# > 0 )) || { echo "wait_cmd: empty command: $desc" >&2; return 2; }
  local deadline=$(( SECONDS + timeout ))
  while :; do
    local remaining=$(( deadline - SECONDS ))
    (( remaining > 0 )) || { echo "wait_cmd: timeout after ${timeout}s: $desc" >&2; return 1; }
    # A retry must not block past the overall deadline. `timeout` is required
    # because mysqladmin/docker commands can otherwise hang indefinitely.
    if timeout "$remaining" "$@" >/dev/null 2>&1; then return 0; fi
    remaining=$(( deadline - SECONDS ))
    (( remaining > 0 )) || { echo "wait_cmd: timeout after ${timeout}s: $desc" >&2; return 1; }
    sleep "$(( remaining < 2 ? remaining : 2 ))"
  done
}
```

`wait_cmd` requires GNU/coreutils `timeout`; §2 checks `command -v timeout`.
The command is attempted only while time remains, and a single attempt cannot
outlive the overall deadline. A malformed invocation (missing `--`, non-positive
timeout, or empty command) returns exit code 2.

### 6.2 `scripts/tools/install_k6.sh`

- 架构：`uname -m` 为 `x86_64` 时用 `amd64`，为 `aarch64`/`arm64` 时用 `arm64`。只支持 Linux。其他平台退出码 3，并提示改用 Docker 镜像 `grafana/k6:2.3.0`。
- 期望的 checksum 直接写死在脚本里（来源：k6 v2.3.0 GitHub Release 的 `k6-v2.3.0-checksums.txt`，2026-10-03 已核对 **[源码]**）：
  - `amd64`：`39c3117b6af817592dcd0ce4242105c0a7af10948c2a425306f0be8f7a8a8ab1`
  - `arm64`：`5ca3433e8201da72a284aaa241a1bb5fb47f4abb4e384d39410ddd8062f49b90`
- 流程：

  ```bash
  set -Eeuo pipefail
  tmp=$(mktemp -d); trap 'rm -rf "$tmp"' EXIT
  curl -fsSL --retry 3 -o "$tmp/k6.tgz" "https://github.com/grafana/k6/releases/download/v2.3.0/k6-v2.3.0-linux-$arch.tar.gz"
  echo "$expected  $tmp/k6.tgz" | sha256sum -c -      # 不匹配时 sha256sum 退出码 1
  tar -xzf "$tmp/k6.tgz" -C "$tmp"
  install -D -m 0755 "$tmp/k6-v2.3.0-linux-$arch/k6" "$TOOLS_DIR/k6-v2.3.0/k6"
  "$TOOLS_DIR/k6-v2.3.0/k6" version | grep -q 'k6 v2.3.0'
  ```

- `TOOLS_DIR` 默认为 `$REPO/.tools`。下载失败退出码 4；checksum 不匹配退出码 5（捕获 `sha256sum` 的失败后映射过去）；版本不对退出码 6。脚本**不得**有任何跳过校验的开关。
- 完成后在 stdout 打印 k6 的绝对路径；调用方自行 `export K6=...`。

### 6.3 `scripts/db/lib.sh`（MySQL 与 Redis 的启动方式）

所有调用都用 bash 数组传参，**禁止**把整条命令拼成一个字符串再展开执行。

```bash
# P0_MYSQL_MODE=docker|local ; P0_TMP=临时目录（mktemp -d 生成） ; DB_PASSWORD=root（仅用于临时实例）
mysql_cli()     { if [[ $P0_MYSQL_MODE == docker ]]; then docker exec -i -e MYSQL_PWD="$DB_PASSWORD" ftsm-p0-mysql mysql -uroot "$@";
                  else MYSQL_PWD="$DB_PASSWORD" mysql --no-defaults --protocol=TCP -h127.0.0.1 -P3307 -uroot "$@"; fi; }
mysqldump_cli() { ...同样的分支，命令换成 mysqldump... ; }
```

- **方式 D（docker）**：容器名 `ftsm-p0-mysql`，带 label `ftsm.phase=p0`，参数为 `-p 127.0.0.1:3307:3306 -e MYSQL_ROOT_PASSWORD=root mysql:8.0.46`。如果同名容器已经存在：label 是 `p0` 且镜像为 `mysql:8.0.46` 时复用；否则退出码 5，**不得**删除这个容器。Redis 容器名为 `ftsm-p0-redis`，参数为 `-p 127.0.0.1:6380:6379 redis:7.4.6-alpine`，规则相同。
- **方式 L（local，无 Docker）**：
  - 支持的平台：Ubuntu 24.04（noble）amd64/arm64。在该平台上 `apt-cache policy mysql-server-8.0` 的候选版本为 `8.0.46-0ubuntu0.24.04.3`（2026-10-03 核实 **[源码]**）。
  - `mysqld --version` 必须匹配 `Ver 8\.0\.[0-9]+`，否则退出码 6。实际版本号记录到 `scripts/db/evidence/p0/mysql-version.txt`；如果不是 8.0.46，在 PR 里说明。
  - 只有在 `command -v mysqld` 找不到、并且设置了 `ALLOW_APT_INSTALL=1` 时，才执行 `sudo apt-get install -y mysql-server-8.0 mysql-client-8.0`。这只用于一次性的云端容器；在个人电脑上**不要**设置这个变量。
  - **不使用、也不修改**系统的 MySQL 服务、`/var/lib/mysql` 和系统的 root 账户。临时实例的启动方式：
    ```bash
    mysqld --no-defaults --initialize-insecure --datadir="$P0_TMP/mysql" --user="$(id -un)"
    mysqld --no-defaults --datadir="$P0_TMP/mysql" --port=3307 --bind-address=127.0.0.1 --mysqlx=OFF \
      --socket="$P0_TMP/mysql.sock" --pid-file="$P0_TMP/mysql.pid" --user="$(id -un)" > "$P0_TMP/mysqld.log" 2>&1 &
    wait_cmd 60 "temp mysqld" -- mysqladmin --no-defaults --socket="$P0_TMP/mysql.sock" -uroot ping
    mysql --no-defaults --socket="$P0_TMP/mysql.sock" -uroot -e \
      "CREATE USER 'root'@'127.0.0.1' IDENTIFIED BY 'root'; GRANT ALL ON *.* TO 'root'@'127.0.0.1' WITH GRANT OPTION; ALTER USER 'root'@'localhost' IDENTIFIED BY 'root';"
    ```
    只修改临时实例自己的账户。
  - Redis：`redis-server --port 6380 --bind 127.0.0.1 --dir "$P0_TMP" --daemonize yes --pidfile "$P0_TMP/redis.pid"`。
- `stop_temp_mysql` / `stop_temp_redis` 只停止由本阶段启动的实例：
  - 方式 D 用 `docker rm -f`，并且只针对带 `ftsm.phase=p0` label 的容器；
  - 方式 L 用 `mysqladmin --socket=… shutdown` 和 `kill $(cat redis.pid)`。

### 6.4 `scripts/db/export_baseline_schema.sh`

3. 输出文件 `backend/src/main/resources/db/migration/V1__baseline.sql` 的处理规则：
   - `git cat-file -e origin/main:<path>` 成功，说明已合并 → **退出码 3，拒绝覆盖**；
   - 已存在但未提交 → 需要加 `--force-overwrite-untracked` 才覆盖，否则退出码 4；
   - 不存在 → 正常写入。
4. 启动基线 jar：参数用数组拼装，环境变量为 `DB_URL=jdbc:mysql://127.0.0.1:3307/ftsm_p0_export?createDatabaseIfNotExist=true&useSSL=false&allowPublicKeyRetrieval=true&serverTimezone=UTC`、`DB_USERNAME=root`、`DB_PASSWORD=root`、`REDIS_PORT=6380`、`SEED_ENABLED=false`、`SERVER_PORT=18080`、`MAIL_ENABLED=false`。启动后执行 `wait_http http://127.0.0.1:18080/actuator/health 180 $pid $log`；返回值非 0 时，杀掉进程，以同样的退出码退出。
5. `kill $pid; wait $pid || true`。
6. 导出：

   ```bash
   mysqldump_cli --no-data --compact --skip-add-drop-table --skip-comments --skip-set-charset ftsm_p0_export > "$tmp/raw.sql"
   ```

7. 清洗（用 `python3`，不用 sed 链）：
   - 删除以 `/*!` 开头的行；
   - 删除以 `SET ` 开头的行；
   - 删除表选项中的 ` AUTO_INCREMENT=\d+`；
   - 在文件头写入注释 `-- V1 baseline: exported from Hibernate DDL at 5f5fae4 (v0.4.2) on MySQL <实际版本>. DO NOT EDIT after merge.`
8. 断言恰好有 6 条 `CREATE TABLE`，表名集合为 `{items, orders, products, reviews, seckill_events, users}`；否则退出码 1。
9. 原子写入：先写临时文件，再 `mv` 到目标路径。
10. 保留原始退出码：主体逻辑放在函数里执行，`trap` 只负责清理，不改退出码。

### 6.5 `scripts/db/schema_fingerprint.sh DB`

对指定库执行下列查询（`--batch --skip-column-names`），按固定顺序拼接后输出到 stdout，所有查询都带 `table_name <> 'flyway_schema_history'` 条件：

```sql
SELECT 'T', table_name, engine, table_collation, create_options
  FROM information_schema.tables WHERE table_schema=DATABASE() AND table_name<>'flyway_schema_history' ORDER BY 2;
SELECT 'C', table_name, ordinal_position, column_name, column_type, is_nullable, IFNULL(column_default,'<NULL>'),
       extra, IFNULL(character_set_name,'-'), IFNULL(collation_name,'-')
  FROM information_schema.columns WHERE table_schema=DATABASE() AND table_name<>'flyway_schema_history' ORDER BY 2,3;
SELECT 'I', table_name, index_name, non_unique, seq_in_index, column_name, IFNULL(sub_part,'-'), index_type
  FROM information_schema.statistics WHERE table_schema=DATABASE() AND table_name<>'flyway_schema_history' ORDER BY 2,3,5;
SELECT 'K', tc.table_name, tc.constraint_name, tc.constraint_type
  FROM information_schema.table_constraints tc WHERE tc.table_schema=DATABASE() AND tc.table_name<>'flyway_schema_history' ORDER BY 2,3;
SELECT 'CK', cc.constraint_name, cc.check_clause
  FROM information_schema.check_constraints cc WHERE cc.constraint_schema=DATABASE() ORDER BY 2;
```

`compare_schemas.sh A B`：生成两份指纹，分别写到 `scripts/db/evidence/p0/<db>.fingerprint.tsv`，再执行 `diff -u`，结果写到 `…/diff-<A>-<B>.txt`。diff 为空时退出码 0，否则为 1。

### 6.6 k6 的业务结果判定（`loadtest/lib/result.js`）

| 后端版本 | 预期 HTTP 状态 | 业务 `result` |
| --- | --- | --- |
| 基线 / P0 / P1（`REJECT_STATUS=200`） | 202 → `ACCEPTED`；200 → `SOLD_OUT`、`ALREADY_BOUGHT` | `NOT_ACTIVE` 视为失败 |
| P2 起（`REJECT_STATUS=409`） | 202 → `ACCEPTED`；409 → `SOLD_OUT`、`ALREADY_BOUGHT` | `NOT_ACTIVE` 和 503 `UNAVAILABLE` 视为失败 |

- 用 `r.json('result')` 解析；抛异常或拿不到值时记为 `UNPARSEABLE`。计数器为 `seckill_results`，tag 为 `{result}`。**[实验]** 已在 k6 2.3.0 上验证按 tag 计数可用。
- 状态码与 `result` 必须一致（202 只能对应 `ACCEPTED`，以此类推）；不一致时另一个计数器 `seckill_mismatch` 加 1。
- throughput 的阈值：

  ```javascript
  'http_reqs{scenario:steady}': ['count>0'],
  'dropped_iterations{scenario:steady}': ['count==0'],          // [实验] 0 时通过，有丢弃时退出码 99
  'seckill_results{scenario:steady,result:ACCEPTED}': ['count>0'],
  'seckill_results{scenario:steady,result:UNPARSEABLE}': ['count==0'],
  'seckill_results{scenario:steady,result:NOT_ACTIVE}': ['count==0'],
  'seckill_mismatch': ['count==0'],
  'http_req_duration{scenario:steady}': ['p(99)<1000'],
  ```

- contention 的阈值：

  ```javascript
  'seckill_results{result:ACCEPTED}':       [`count==${STOCK}`],
  'seckill_results{result:SOLD_OUT}':       [`count==${BUYERS - STOCK}`],
  'seckill_results{result:ALREADY_BOUGHT}': ['count==0'],
  'seckill_mismatch':                       ['count==0'],
  'http_req_failed':                        ['rate==0'],
  ```

  阈值未满足时 k6 退出码为 99 **[实验]**。
- 稳定阶段的 QPS 一律用 `count / STEADY_SECONDS` 计算，**不能**用导出数据里的 `rate`：k6 的子指标 `rate` 是除以整个测试时长得到的 **[实验]**。`handleSummary` 写出的 `meta` 包含：`runId`、`script`、`rate`、`rampSeconds`、`steadySeconds`、`requestRps`（= 稳定阶段请求数 / steadySeconds）、`acceptedRps`（= 稳定阶段 ACCEPTED 数 / steadySeconds）、`eventId`、`rejectStatus`、`baseUrl`、`k6Version`。
- 用户 ID：`USER_BASE + exec.scenario.iterationInTest`，steady scenario 再加上 `50_000_000`。`USER_BASE` 由 `run.sh` 传入，计算方式为 `1_000_000_000 + (runSeq × 100_000_000)`，`runSeq` 是当天的运行序号。

### 6.7 `loadtest/run.sh`（一次运行 = 一个目录）

```text
loadtest/run.sh --config <A-baseline|P0|...> --scenario <throughput|contention> --base URL \
                --jwt-secret-env JWT_SECRET --stock N [--buyers N --vus N | --rate N --ramp S --steady S] \
                --reject-status 200|409 --drain stream|outbox|none --mysql temp:<db> --redis temp --out-root loadtest/results/_smoke
```

0. `--mysql` 和 `--redis` 指定 verify 与 drain 访问哪个实例。P0 只实现 `temp:<db>` 和 `temp`，即 `scripts/db/lib.sh` 启动的临时实例（127.0.0.1:3307 / 6380）。后续阶段在 `scripts/db/lib.sh` 中扩展：P2 增加 `compose:<project>:<env-file>:<db>`（通过 `docker compose -p … --env-file … exec -T mysql|redis` 访问），P6b 增加 `k8s:<ns>:<db>`。遇到不认识的目标时，退出码 2。
1. 生成 `RUN_ID=$(date -u +%Y%m%dT%H%M%SZ)-<config>-<scenario>`。目录 `<out-root>/<config>/<RUN_ID>/` 已存在时退出码 2，**不复用旧结果**。
2. 调用 `setup_event.py` 新建活动，从它的 JSON 输出读取 `eventId`，写入 `run.json`。
3. 运行 k6，`SUMMARY_PATH=<dir>/summary.json`，记录 k6 的退出码 `k6_rc`。
4. 调用 `drain.sh <mode>` 等待消息处理完毕（`stream` 模式：最多等 120 s，直到 `XPENDING seckill:orders seckill-order-consumers` 的计数为 0，**并且** `XINFO GROUPS seckill:orders` 中的 `lag` 为 0）。超时则退出码 3。
5. 执行 `verify.sql`（设置 `@event_id`），结果写入 `<dir>/verify.tsv`；同时取 Redis 中剩余的库存，写入 `<dir>/redis.txt`。
6. 核对：`verify.orders == verify.buyers == meta.accepted`（accepted 为整个测试期间的 ACCEPTED 计数）；contention 场景下还要求 Redis 剩余库存为 0。不一致时退出码 4。
7. 写入 `run.json`：`runId`、`gitSha`、`config`、`eventId`、`startedAt`、`finishedAt`、`k6_rc`、`drain_rc`、`verify_ok`，以及记录下来的环境信息。
8. `run.sh` 的最终退出码：`k6_rc` 不为 0 时取 `k6_rc`，否则取第 4–6 步中第一个非 0 的退出码。

`summarize.py --dir <out-root>/<config>`：只读取同时含有 `run.json`、`summary.json`、`verify.tsv` 并且 `run.json.eventId == summary.meta.eventId` 的目录；不满足的目录列为 invalid，并以退出码 1 结束。

start_backend() {
  local jar=$1 db=$2 port=$3 log=$4
  env DB_URL="jdbc:mysql://127.0.0.1:3307/$db?createDatabaseIfNotExist=true&useSSL=false&allowPublicKeyRetrieval=true&serverTimezone=UTC" \

## 10. 升级、重跑与恢复

1. **已有数据如何升级**：已有的数据库第一次启动 P0 代码时，Flyway 会自动把它基线化，不改动任何表。可以用 A7 中 legacy 库的流程，在副本上演练一遍。
2. **重复执行是否安全**：
   - tag：已存在且指向正确时跳过；指向其他提交时停止。
   - 导出脚本：重建 `ftsm_p0_*` 库；拒绝覆盖已合并的 V1。
   - `run.sh`：每次运行使用新目录，拒绝复用。
   - 临时容器：按 label 判断是否复用。
3. **失败后的恢复**：
   - 删除本阶段创建的资源：`docker rm -f $(docker ps -aq --filter label=ftsm.phase=p0)`；方式 L 下执行 `stop_temp_mysql; stop_temp_redis; rm -rf "$P0_TMP"`；`git worktree remove --force "$P0_TMP/baseline"`。
   - **不得**删除用户自己的 compose 卷，也不得改动 `ftsm_ecommerce` 库或用户已有的 MySQL 服务。
4. **数据库降级**：不支持自动降级。如果需要回退到 P0 之前的代码，只要删除 `flyway_schema_history` 表即可（V1 本身没有修改任何表结构）；把这条手工命令写进 README 的 “Database migrations” 一节。
